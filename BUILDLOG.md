## 2026-08-30 — Hosted-tier economics: the letter loop and the disarmed budget
- **Letter loop (would have started billing at G5):** the Monday letter's only dedupe was the idempotency header on `POST /ask` — but `hostedLlmJson` ran BEFORE the write, every cycle, for as long as the last settled week stayed newest. Post-G5 that is ~144 wasted LLM calls per hosted agent per day, forever, and the §3.1 budget kill-switch pauses signups only (never in-season cycles, by binding rule), so the spend would just accumulate. Now a durable `hosted_letter` events marker (team+week) is checked BEFORE the prompt is built; the marker is written only after a 2xx/409, and a `hosted-letter-try` rate bucket caps retries at ≤4/day/team-week so a jammed ask-cap can't burn inference either.
- **Letter also escaped its cage:** the block was nested under "this league has an open matchup", so the FINAL settled week of a season — the one with the most to say — could never produce a letter. Now it runs whenever a settled week exists.
- **Budget could not trip:** per-call spend was `Math.max(1, round(usage.cost * 1e6))`, so a provider response that omits `usage.cost` recorded **1 microUSD** — $10/month would never be reached no matter the real spend. Now an absent/zero cost bills a conservative per-model `fallbackMicroUsd` from the menu (hermes/flash 1000µ$, haiku 10000µ$; unknown ids charge the menu max) and raises a once-per-day-per-model `hosted_cost_fallback` event.
- **Verification:** 227/227 · 3 new hosted tests — letter generated exactly once across two ticks (fetch-spy counts OpenRouter calls; the pre-fix regression), a 429'd post leaves no marker and the retry is rate-bound, and fallback pricing accrues 2×1000µ$ with one breadcrumb while a reported cost takes precedence · typecheck + marks clean. All inert until `HOSTED_OPEN=1` at G5.

## 2026-08-30 — Idempotency replays are caller-scoped (credential-replay fix)
- **The defect (adversarial review, security lane):** the replay store was keyed (key, route) with no caller — so ANY two callers sharing an Idempotency-Key string shared stored responses. Worst case was `POST /register`: its stored 201 body carries the plaintext `api_key`, so `-H 'Idempotency-Key: test'` returned whichever registrant used "test" first — cross-tenant credential disclosure, live since Phase A. Second-order: hosted-tier keys are predictable (`hosted-<teamId>-pick-<n>`), so a league rival could pre-poison a shared route and silently suppress a victim's write into a replay of the attacker's response.
- **The fix (migration 0009):** new `idempotency_keys` table keyed **(actor, route, key)** — actor = the authed agent id (`agentAuth` always runs first; the order is now documented as load-bearing), or for the two anonymous routes (`/register`, `/hosted`) a sha256 of client IP + declared `owner_email`. IP must be in the hash: an email-only actor would let an attacker who knows a victim's address pre-store a response whose api_key the attacker controls. Tradeoff accepted: a register retry from a rotated egress IP misses the replay and gets the documented 409 NAME_TAKEN instead. Old table dropped (pure cache; in-flight retries across the deploy minute lose replay once, acceptable pre-launch).
- **At-rest exposure bounded:** replay rows now expire — `sweepReplayCache` (rides the 6h sync) deletes rows >48h old plus rate windows >8 days. Storing the register body at all is unavoidable (a replay must return the one-time key, which exists only as a hash afterwards) — scoped + swept is the accepted deviation from "hashes only", recorded in DRIFT.
- **Also:** `model` is now tag-stripped at the register boundary like every other stored string (F4 hygiene; all sinks already escaped).
- **Verification:** 3 new tests (cross-caller register isolation with same key — the attack regression; cross-agent authed-route isolation + true-owner replay; 48h sweep purges old rows, keeps fresh) · routes-register replay test updated to pin its IP (a genuine retry comes from the same host — that's the semantic) · redteam gains a "shared key never crosses callers" section (98 checks) · full suite + typecheck + marks green.

## 2026-08-30 — Settlement completeness gate: the Week-1-zeros landmine, defused
- **The defect (found by the owner-directed full-repo adversarial review, four independent reviewers):** `settleDueWeeks` treated ANY `stats_weekly` row for (season, week) as "week is due" — but nflverse republishes the season stats file nightly WHILE a week is in progress, so the night after Thursday's opener, week 1 would have settled across every league with only TNF players scored and zeros everywhere else, permanently (`settled_at` latches), with belt/recap/cards publishing on the garbage. Invisible until now because fixtures deliver a week's stats as one complete file. Would have fired **Fri Sep 11**.
- **The gate:** a week is due only when stats exist AND every game of the week has ≥1 stat line from either club (coverage via `games`⋈`players.team` — clock-free, identical semantics for fixtures and empty-games dev DBs), OR the week's last kickoff is >48h old (deadman for a cancelled game that will never get stats; logs `settle_forced`). Memoized per (sport, season, week) per invocation.
- **Settlement latch (new `settlements` table, migration 0008):** cron triggers collide at :00 (`*/10` vs `0 */6` vs Tue 15:00) and could double-post events/recaps. Now exactly one invocation claims a (league, week) via `INSERT..ON CONFLICT DO NOTHING` (+10-min stale takeover); `week_settled`/`belt_won`/`settle_forced` events and the latch marker commit in ONE transaction. Score UPDATEs stay re-runnable; belt now computed from STORED scores so a takeover mid-week stays correct.
- **Recaps are DB-driven and durable:** `recapSettledWeeks(db, env)` scans the latch for settled-but-unrecapped weeks (10-min recap claim + stale takeover) instead of trusting the in-memory settle outcome — a crash, subrequest-ceiling abort, or failed Anthropic call self-heals forever. Message + news event + `recap_posted_at` commit atomically.
- **Stats sync decoupled:** `syncWeekStats` takes a week SET (one CSV fetch, N upsert passes) and the crons target the distinct unsettled weeks (≤3), not the global MIN — one wedged league can no longer starve every other league's stats. The `,season,week,REG,` substring prefilter is now header-verified (adjacency proven each run; falls back to full parse) so an upstream column reorder can't silently produce "0 rows" forever.
- **Season advancement hardening (same review):** completion now computes champion/roast BEFORE any write and commits status+events in one transaction (the old latch-first order could crash into a `complete` league with no champion event, unrecoverable); `playoffs_set`/`roast_announced`/`champion_crowned`/`roast_target` are NOT-EXISTS-guarded inserts under SQLite's single writer (no duplicate feed events at :00 collisions); consolation tie now goes to higher regular-season PF (home/away is round-robin-arbitrary there — DRIFT rule pin), belt tie to higher season PF then teamId; per-league try/catch fault isolation (`cron_error` events) in settle + advance, so one malformed league can't stall the fleet.
- **Verification:** 221/221 (7 new: partial-stats refusal regression · coverage settles · 48h backstop + `settle_forced` · concurrent double-settle → one event set · fresh-claim defers/stale-claim adopted · recap crash self-heal · broken-league isolation + `unsettledWeeks` multi-week) · typecheck + marks clean. Also fixed a latent test flake: retention's belt assertions assumed members[0]/[1] never meet in week 1, but pairings hash random team UUIDs — now scores a known matchup pair.
- **Open:** migration 0008 applies on prod at the next deploy (single CREATE TABLE, per-statement-safe by construction).
